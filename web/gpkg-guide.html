QGIS GUIDE · GEOPACKAGE FILES FOR NEW GIS TECHNICIANS

One file. Data,
style, and layout.

Every project you'll work on comes as a single .gpkg file, opened in QGIS. It already contains the map project, the layers, the way they're styled, and any print layouts. This guide explains how to keep it that way when you swap in new data — plain language, no assumed experience.

Tool QGIS (Desktop) File type .gpkg
01

What's Actually in the File

One bundle, four things

Normally a GIS handover is a mess of separate files — a shapefile here, a style file there, a project file pointing at both. Move one file and the rest breaks. A .gpkg avoids that: it's a single file that already contains everything.

Because everything sits inside one file, copying that single .gpkg to another computer and opening it should give you back the exact same map, colors, and print pages — nothing to relink by hand.

Worth remembering

  • The style belongs to the database, not to QGIS. It's saved inside the file, attached to the layer by name.
02

Opening the Project Correctly

Don't just drag the file in

If you drag the .gpkg straight onto the QGIS map canvas, you'll only get a flat list of layers — no groups, no saved styling setup, no layouts. Open the project that's saved inside the file instead:

  1. In QGIS, go to Project > Open From > GeoPackage…
  2. Pick the .gpkg file, then select the project listed inside it.
Before changing anything, take a minute to look at what's already there: the layer names in the Layers panel, and the pages in Project > Layouts…. That way, if something looks different later, you'll know exactly what changed.
03

Updating Data

The everyday task

Most of the time, "to update the data" means switching a different layer/version of the same dataset into the same project — new survey points, a refreshed boundary file, this month's readings. There are two ways to do it, and one is much safer than the other.

Adding new records

If you're just adding rows to a layer that already exists — nothing about its columns/attribute fields is changing — copy the new features in and paste them into the existing layer's attribute table, or digititalize them by hand before filling in their form. Nothing about the layer's identity changes, so its style and any print page using it keep working automatically.

Replacing the whole layer

If you're replacing a layer with a new version, import the new layer but don’t delete the old one yet.

Right-click the old layer and select Styles > Copy Style > All Style Categories

Then, right-click the new layer and select Styles > Paste Style > All Style Categories

You can also access all saved styles via Layer Properties > Style > Load Style >
From Database (GeoPackage)

If the style doesn’t apply correctly, check that the field names used for styling have not changed between versions.

After any update, close the project and open it again — don't just refresh the layer. That's the surest way to see whether the style and layouts followed the new data.
04

Keeping the Styling

How QGIS finds the right style

When saving a style as default to the databsase, QGIS will save the layer name it has been assigned to, QGIS then finds a saved style by matching the layer's name to its style inside the file. As long as the layer name stays the same, the style follows automatically — you don't need to reapply it.

Saving a style so it travels with the file

If you build or adjust a style, save it back into the .gpkg so the next person gets it too:

  1. Right-click the layer> Export > Save as QGIS Layer Style File.
  2. Choose"Save style: Save in database (GeoPackage)" — not "As QGIS QML Style File".
  3. Optionally give it a name(if empty, defaults to layer name) anddon't forget to check"Use as default style for this layer"
05

Print Layouts

The one thing worth double-checking

Layouts (print pages) are saved inside the project too, so they travel with the file the same way styles do. The one setting worth knowing about is the map theme — I use it to drive the map style on unique layer within my projects.

In QGIS layouts, a map element can either follow the current map theme, or be locked to a fixed one. A locked theme is great for a layout that always features multiples maps, without this following fix it may not render on export the way it does in QGIS..

For single map layouts. Go to: Item Properties > Layers > Follow map theme

For multi-maps layouts. Go to: Item Properties > Variables > + and add the variable current_theme — give it for value the name of the theme you want to target

06

What Usually Breaks a Style

A short list, not an exhaustive one
What happened What you'll see
The new layer was imported under a different name, or the old one was deleted and a "new" one added The layer doesn't show up with the saved style
A column the style relies on (for coloring or labels) was renamed or removed Everything draws in one flat color, or not at all
A layout's map frame is locked to an old area The printed page looks empty or cuts off the new data
The logo folder is missing or has been renamed. The DDAs logos are missing
Notice the pattern: in every case, the data is fine — it's just that something QGIS was matching by name no longer matches. Nothing here means your data is broken.
07

Quick Fixes

Matched to the causes above

The style is gone, but the layer name is right

  1. Right-click the layer > Properties > Symbology > Style > Load Style…
  2. Choose the style saved in the database.

Colors went flat/transparent

  1. Open Symbology and check the field it's using — "field_name"the new data might lack this field or its name has changed.
  2. Simply modify the double-quoted text to its new matching value.
08

Backups

One habit, five seconds

Before updating anything, copy the .gpkg file and give the copy today's date — for example parcels_2026-08-19.gpkg. Because everything lives in one file, that copy is your only way back if an update goes wrong. It costs a few seconds and it's the single most useful habit in this guide.
