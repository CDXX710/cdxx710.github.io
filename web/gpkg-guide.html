QGIS GUIDE · GEOPACKAGE FILES FOR NEW GIS TECHNICIANS

One file. Data,
style, and layout.

Every project you'll work on comes as a single .gpkg file, opened in QGIS. It already contains the map project, the layers, the way they're styled, and any print layouts. This guide explains how to keep it that way when you swap in new data — plain language, no assumed experience.

Tool QGIS (Desktop) File type .gpkg
01

What's Actually in the File

One bundle, four things

Normally a GIS handover is a mess of separate files — a shapefile here, a style file there, a project file pointing at both. Move one file and the rest breaks. A .gpkg avoids that: it's a single file that already contains everything.

Because everything sits inside one file, copying that single .gpkg to another computer and opening it should give you back the exact same map, colors, and print pages — nothing to relink by hand.

Two things worth remembering

  • The style belongs to the layer, not to QGIS. It's saved inside the file, attached to that layer by name. It isn't a setting on your computer.
  • Everything is matched by name. QGIS finds a layer's style by looking for a layer with the same name. That's the one rule behind almost everything in §5.
02

Opening the Project Correctly

Don't just drag the file in

If you drag the .gpkg straight onto the QGIS map canvas, you'll only get a flat list of layers — no groups, no saved styling setup, no layouts. Open the project that's saved inside the file instead:

  1. In QGIS, go to Project → Open From → GeoPackage…
  2. Pick the .gpkg file, then select the project listed inside it.
Screenshot needed

The Project → Open From → GeoPackage… menu, and the file-picker dialog showing a project selected inside a .gpkg.

Before changing anything, take a minute to look at what's already there: the layer names in the Layers panel, and the pages in Project → Layouts…. That way, if something looks different later, you'll know exactly what changed.
03

Updating Data

The everyday task

Most of the time, "update the data" means putting a newer version of the same layer into the same project — new survey points, a refreshed boundary file, this month's readings. There are two ways to do it, and one is much safer than the other.

Adding new records

If you're just adding rows to a layer that already exists — nothing about its columns is changing — copy the new features in and paste them into the existing layer's attribute table. Nothing about the layer's identity changes, so its style and any print page using it keep working automatically.

Replacing the whole layer

If you're swapping in a full new version of a layer (same columns, just newer data), import it and choose to overwrite the existing layer — keep the exact same name. Don't delete the old layer and add the new one as if it were fresh; that's the one habit most likely to disconnect the style, explained in §5.

Screenshot needed

The import dialog (Database → DB Manager → Import Layer/File…) with the Overwrite option and the matching table name visible.

After any update, close the project and open it again — don't just refresh the layer. That's the surest way to see whether the style and layouts followed the new data.
04

Keeping the Styling

How QGIS finds the right style

QGIS finds a saved style by matching the layer's name to a style with the same name inside the file. As long as the name stays the same, the style follows automatically — you don't need to reapply it.

Saving a style so it travels with the file

If you build or adjust a style, save it back into the .gpkg so the next person gets it too:

  1. Right-click the layer → Properties → Symbology.
  2. Click Style → Save Style…
  3. Choose "Save in database (GeoPackage)" — not just "Save to file".

05

Print Layouts

The one thing worth double-checking

Layouts (print pages) are saved inside the project too, so they travel with the file the same way styles do. The one setting worth knowing about is the map frame's extent — the area it shows.

A layout's map frame can either follow the current map view, or be locked to a fixed area. A locked extent is great for a page that always needs to show the same region — but if your new data covers a different area than the old data did, a locked frame will just keep showing the old area, cropping out anything new.

Screenshot needed

The Layout editor's map item properties panel, showing the lock/extent controls under the "Main properties" section.

After updating data, open every layout — not just the one you expect to be affected — and check it still frames the right area.
06

What Usually Breaks a Style

A short list, not an exhaustive one
What happened What you'll see
The new layer was imported under a different name, or the old one was deleted and a "new" one added The layer shows up with random default colors instead of the saved style
A column the style relies on (for coloring or labels) was renamed or removed Everything draws in one flat color, or labels disappear
A layout's map frame is locked to an old area The printed page looks empty or cuts off the new data
Notice the pattern: in every case, the data is fine — it's just that something QGIS was matching by name no longer matches. Nothing here means your data is broken.
07

Quick Fixes

Matched to the causes above

The style is gone, but the layer name is right

  1. Right-click the layer → Properties → Symbology → Style → Load Style…
  2. Choose the style saved in the database.

Colors or labels went flat

  1. Open Symbology and check the field it's using to color the map — it may show blank or crossed out.
  2. Pick the matching field from the new data and re-apply.

A layout page looks wrong

  1. Click the map frame → check it's pointed at the right layer.
  2. If the extent is locked to an old area, reset it to match the new data.
If none of these fix it, stop and go back to your last backup (§8) rather than trying something bigger — it's faster than untangling a second problem on top of the first.
08

Backups

One habit, five seconds

Before updating anything, copy the .gpkg file and give the copy today's date — for example parcels_2026-08-19.gpkg. Because everything lives in one file, that copy is your only way back if an update goes wrong. It costs a few seconds and it's the single most useful habit in this guide.

09

Checklist

Run through this every time
  1. Make a dated backup copy of the file.
  2. Open the project from the GeoPackage, not by dragging the file in.
  3. Update the data — add rows, or overwrite the layer keeping the same name.
  4. Close and reopen the project to check styles carried over.
  5. Open every layout and check it still frames the right area.
  6. If a style needed reloading, save it back into the file for next time.
